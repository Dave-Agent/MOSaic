# scripts/refactor

The primitives every phase 1 (and phase 2) pass needs, taking a TSV map. All of them: `--root DIR`, `--phase 1|2` or `--main FILE` (the source is the main file's directory, `libs/`
excluded), **dry run by default** (they print what they would change), `--write` applies. They change names and comments only, never bytes: run the byte-identity gate after each.
They rewrite the CODE part of a line only (never a `// comment` and never a "string"; `rename.py --comments` and `drop_labels.py --comments` also rename prose mentions, never the
XREF or `[ADDR:bytes]` trace comments). Text before `//` in a TSV cell is literal; `\n` in a comment cell starts a new paragraph. **A line break inside a cell is always the two characters backslash-n, never a real newline**: a real newline splits the row, and every tool (and `add_label.py --map`) stops with `file:LINE: bad map row` naming the line. Several TODOs go in column 4 as `TODO(name): a\nTODO(user): b` (a fifth column is refused, not dropped).

| tool | map | what it does |
|---|---|---|
| `rename.py MAP` | `OLD<TAB>NEW[<TAB>description[<TAB>TODO(tag): text]]` | rename labels everywhere; refuses a NEW that already exists; a description becomes a wrapped `// NEW: ...` block ABOVE the definition's XREF lines (the place `set_comment.py` writes; both call `_common.set_block`): an older block there is replaced and reported ONLY when it is recognisably a description (at most `--max-replace` = 8 own-line lines, no section banner, no XREF / register-access notes like `1a2b(R)`, not a note that opens `// OTHER: ...`; its TODO paragraphs survive); any other block is KEPT, the new text goes after it and `REVIEW kept ...` is printed (nothing is swallowed; `--keep-old` keeps always); the fourth column is written as its own `// TODO(tag):` line(s) below it; `--comments` also renames prose mentions and LISTS every comment line it changed |
| `drop_labels.py MAP` | `OLD<TAB>EXPR` | delete `.label OLD = ...` (and its XREF continuation lines) and write EXPR (`tbl+1`, `Scope.name`) at every use: a variable that is really a byte of another label |
| `replace_raw.py MAP` | `HEXADDR<TAB>EXPR` | raw `$ADDR` code operands to a label (`--words`: also `.word $ADDR`); the targets come from `raw_refs.py -v` |
| `replace_imm.py MAP` | `INSTRADDR<TAB>EXPR` | the immediate of the instruction at that original address becomes `#<label` / `#>label` (address pairs listed by `addr_immediates.py`) |
| `move_img.py MAP` | `OLD<TAB>NEW[<TAB>description]` | an image-resident variable `.label OLD = $ADDR` becomes an in-stream label `NEW:` at that address (instruction or `.byte` row split), carries its XREF text and description, renames the uses. An address inside an instruction becomes the SMC operand form `NEW:operand` + `SMC` marker |
| `scopeify.py SPEC` | `ROUTINE<TAB>summary<TAB>old=new;old=!;...[<TAB>inner;labels]` | wrap routines as `Name: {` ... `} // Name`, name the local labels, turn the `=!` ones into anonymous labels (`!+`, `!-` counted), qualify outside uses as `Name.local` |
| `set_comment.py LABEL TEXT` / `MAP` | `LABEL<TAB>text[<TAB>summary[<TAB>TODO(tag): text]]` | set or replace the block comment above a label (above its XREF lines), wrapped at 124, with the same replace-only-a-description rule as `rename.py` (`--max-replace`, `REVIEW kept ...`); `--summary` sets the label-line summary (an empty cell leaves it, `-` clears it); `--drop-todo` (or `-` in the fourth column) removes the TODO paragraph(s) of the block it replaces, otherwise they survive; the fourth column / `--todo` is written as its own `// TODO(tag):` line(s) after the text. A `TODO(tag):` in the middle of a paragraph is split off the same way (rules.md: a TODO has its own line), so `p1_complete.py` and `todo_list.py` see it |
| `alias.py MAP` | `OLD<TAB>NEW<TAB>BASE<TAB>OFFSET` | element aliases: `.label OLD = $ADDR` is renamed NEW at every use, its definition (and XREF continuation lines) removed, and `.label NEW = BASE+OFFSET` defined once right after BASE's label (after earlier aliases of BASE, so the map order is kept); a description block above OLD moves with it. The alternative to `drop_labels.py` when the element deserves a name of its own (a pointer high byte of a table word, voice 2 of a per-voice array) |
| `note.py MAP` | `ADDR<TAB>text` | own-line comment(s) above the instruction / `.byte` row at that ORIGINAL address (indented like the code, below its label and XREF lines), wrapped; idempotent; a different note already there is kept unless `--replace` (which is also how a note is corrected). An address inside an instruction is refused |
| `uses.py NAME\|$ADDR ...` | | read-only: every reader and writer of a variable (R/W/RW, original address, the enclosing ROUTINE, the nearest label as a second column): the input of the variable-role protocol. The routine is the scope, or the nearest label above that is a `jsr` target, a `jmp` target from another routine (or, with `--flags PREFIX`, anything the tracer saw called or interrupted to), so before the scopes exist the uses are not all "in `LAB_xxxx`" |
| `bitskip.py MAP` / `--scan` | `ADDR<TAB>NAME[<TAB>OLD_LABEL[<TAB>accept]]` | the BIT-skip trick (rules.md): `.byte $2C` (or `$24` / a NOP skip opcode) plus the hidden instruction on its own labelled line, both trace comments kept, the old `LAB_xxxx_1` renamed and its `.label` dropped, the BIT's unused operand label dropped. `--scan` lists the sites (a skip opcode whose operand bytes a branch enters). It prints both readings and the branch that reaches the hidden instruction with the condition it proves, and WARNS when the name may describe the wrong side; a reviewed warning is acknowledged with `--accept NAME[,NAME]` or the word `accept` in column 4: it is then listed once, quietly, as `accepted after review` |
| `table_words.py SPEC` | `ADDR<TAB>word\|field\|lo\|hi<TAB>COUNT<TAB>LAYOUT[<TAB>NAMES]` | raw pointer bytes to names: `.word label` rows, the address word of every record of a record table (`8+6` = stride 8, word at +6; the bytes around it stay `.byte` rows), the `<(base+n)` / `>(base+n)` byte tables of a split pointer table. NAMES: a list, `base:STEP`, or `auto` (the label at the address the bytes already point to). Every entry is checked against the bytes in the table, so the conversion cannot change one |
| `records.py LABEL --stride N [--end HEX] [--header K]` / `--map` | `LABEL<TAB>STRIDE[<TAB>END[<TAB>HEADER]]` | reshape a table's `.byte` rows to one record per row (the exporter's 16-byte rows split records and hide where a list ends); the bytes after an end marker are reported and left alone |
| `bytes_to_code.py --range LO-HI [--names F] [--locals F] [--imm F] [--scope NAME]` | name maps `ADDR<TAB>NAME` | `.byte` rows that are really code become instruction lines with `[ADDR:bytes MNEMONIC]` trace comments, labels, named operands and `#<label` immediates (the one-off script of a slice, made generic). Refuses a range that cuts an instruction, an undocumented opcode (probably data; `--allow-illegal`), an unnamed branch target inside the range, rows that differ from the reference image; re-encodes every instruction and compares it with its bytes; checks operand names against the build's `.sym` when there is one. Existing labels between rows are kept. Run `just verify` after it |

`selftest.py` (no project needed; `python3 -B scripts/refactor/selftest.py [-v]`) runs positive and negative cases of the tools on tiny synthetic sources: what a description may replace, map-file newlines, `--accept`, `anon_labels.py --check` scope crossing, `bytes_to_code.py`, `p1_complete.py` check 7. Run it after changing a tool.

`scripts/add_label.py ADDR NAME [COMMENT]` (one in-stream label; the comment may be several wrapped paragraphs; `--map FILE` with lines `ADDR<TAB>NAME[<TAB>comment]` adds many in one call, `--group TEXT`
puts the description of the whole group on the first label) and the analysis tools `raw_refs.py`, `addr_immediates.py`, `addr_tables.py` (pointer-table candidates in `.byte` rows, with their targets and
the label there), `anon_labels.py` (`--check` also fails on an anonymous reference that crosses a routine boundary: a `beq !-` whose target is in the previous scope, or past a called global entry label), `comment_check.py` (`--fix` re-wraps own-line comments wider than `--wrap`: comments only), `todo_list.py` (the `TODO(user)` / `TODO(name)` / `TODO(block)` markers with the label and routine they sit on, grouped by tag, `--range`; for the log
and for the questions to the user), `p1_complete.py` (`--range LO-HI` reports one slice; it also reads the data rows: pointer-table candidates, unlabelled data runs, and says when a range holds no
instruction at all; check 7, review only: `.byte` rows the tracer EXECUTED, from `--flags PREFIX` or the project's coverage flags, see coverage/raw_executed.py) belong to the same loop.

## The pass order that kept the gate green

Each step: run the tool, `just verify` (byte-identical), commit. The order matters because a later pass needs the names of the earlier one.

1. `symbols_tidy.py` (split the exporter's symbols into `zero_page.asm` / `variables.asm` / `constants.asm`), `just verify`.
2. **Names first.** `rename.py` for routines (`SUB_`/`LAB_` that turn out to be entries) and for zero-page / low-RAM variables (with descriptions). Use `uses.py NAME` to see who writes and reads a variable before naming it.
3. **Image variables to in-stream labels.** `move_img.py` (variables inside the image), `add_label.py` for tables and entry points that have no label yet (`raw_refs.py -v` says which addresses are used most).
4. **Expressions.** `drop_labels.py` for the bytes that are `table+1`, a high byte (`ptr+1`) or an alias.
5. **Raw operands.** `replace_raw.py` (and `--words`), `replace_imm.py` for the `#<`/`#>` pairs. `raw_refs.py` must reach 0 for the slice.
6. **SMC operands.** `move_img.py` on the operand-byte labels (`NEW:operand`), `drop_labels.py` for the second byte (`NEW+1`), then write the `// SMC: <kind> patched by <routine>` line by hand.
7. **Scopes, locals, anonymous labels.** `scopeify.py` with a spec per routine, then `anon_labels.py` for the remaining candidates, `align_comments.py`.
8. **Comments last.** `set_comment.py` for routine and variable blocks, `note.py` for the per-line "say why" notes, banners and `TODO(name)` markers by hand, `just align` (it changes many end-of-line comments after every insert, whitespace only: run it BEFORE) then `comment_check.py` (`--fix` for over-wide own-line comments); `p1_complete.py --range LO-HI --allow-marked` to call the slice clean.

Rules of thumb: dry-run first and read the per-name counts (a name with 0 uses is a typo in the map); never rename two names to one; a label used from another routine stays global
(`scopeify.py` rewrites such a use as a path, and refuses to make it anonymous); keep every `[ADDR:bytes MNEMONIC]` comment. Work in a scratch copy when a map is new.

## Cases that come up (expected treatment)

- **A routine whose code is physically split** (a ramp-down or brake tail that sits after another routine's code, reached by a jump) cannot be one scope: a scope is one contiguous
  range. Each piece is its own scope with its own global name, and a comment on each says which routine it continues. That is the expected treatment, not a gap in the tool.
- **The INNER column of `scopeify.py`** lists labels that sit inside the routine's range but are not branch targets of it: the label of a hidden instruction (the BIT-skip trick, `bitskip.py`),
  a string or table label inside the code, an SMC operand label. Without it the routine would end at such a label (it ends at the next label that is neither a local nor inner). Whenever a
  scope stops short of its `RTS`, look for an inner label.
- **The BIT-skip trick** (`bitskip.py`): the hidden instruction's label already has its final name from `bitskip.py` (run it first: it renames the old `LAB_xxxx_1`); `scopeify.py` then needs it in INNER, because it
  is a label inside the routine that is not a branch target to rename (the branch that reaches it is in the same routine, so the name resolves in the scope). Name the label for the case the BRANCH-TAKEN condition proves; the tool prints that condition.
- **Rows left behind by `move_img.py` / `add_label.py` / `table_words.py`**: splitting a `.byte` row at a label leaves short rows (a 1-byte `.byte $00 // [2188]` between two labels) and the
  blank-line rule wants a blank line before each new top-level label. Both are cosmetic and byte-neutral; `just align` (`align_comments.py`) tidies the blank lines, and nothing needs the rows
  joined again.

**Shared labels inside a scope.** A label inside a scope that another routine references (a shared `rts`) must be listed INNER, and the outside use written as `Scope.name` by hand: `scopeify.py` does not rewrite uses of INNER labels. In `add_label.py --map` a newline inside a comment cell is the two characters `\n`, never a real newline.

**Value tables are not pointers.** `p1_complete.py` check 5 (and `addr_tables.py`) can flag a table of values (note frequencies, pattern numbers, screen positions) as a pointer table. Mark it in the source with `// NOT-POINTERS: reason` on the table's label line (or on its own comment line directly above the label, or on a `.byte` row): it is then listed as waived and counted, not reported, and the marker survives in the source. Words that mostly land inside instructions are dropped by the heuristic without a marker (`addr_tables.py --no-interior` keeps them). Real candidates are never hidden: only a marked table is waived.
