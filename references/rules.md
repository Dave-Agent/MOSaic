# Rules
Shared rules; each section says which projects and phases it applies to. Related pages: `naming.md` (all naming), `layout.md` (file tree, ROMs), `just.md` (command runner), `phase2_port.md` (the setup for a port), `kick.md` (assembler gotchas), `decisions.md` (why).

## Assembler and code
Applies to: every project. The no-raw-address rule gates phase 1; phase 2 keeps it.
- Kick Assembler; `.label name = $ADDR`; `//` comments.
- **No raw addresses in code operands** (phase 1): give the target a label; `#<label` / `#>label` for half an address; `.word label` in data; image bytes get **in-stream labels**, not `.label X = $ADDR` for an address inside the image. `scripts/raw_refs.py` (or the project's `just rawops`) must report 0. Offsets that are constants (`+$64`, `-$ff`) are fine.
- **Self-modifying code:** name the operand with `label:operand` (`ldx mod_value:#$00`, `lda mod_addr:$0000`; high byte `mod_addr+1`, no alias label), add an `SMC Warning` comment / `// SMC: <kind> patched by <routine>` line, and a trailing `SMC` marker. A named alias only for an operand with a meaning of its own. `scripts/smc_list.py` lists them.
- A table that overlaps code is labelled on the instruction operand (`jmp timer_hi_tbl:Routine.label`).
- Keep every `[ADDR:bytes MNEMONIC]` reference; comments after it are encouraged.
- **Code hidden in an operand (the BIT-skip trick).** An instruction whose operand bytes are another instruction, entered at the operand by a branch or jump (`2C A9 00` is `BIT $00A9` when run in sequence and `LDA #$00` when entered at the `A9`; `$24` and a few NOPs work the same way). Write the opcode as `.byte $2C` with a comment saying it hides the next instruction, and put a **label on the hidden instruction** (`turn_resume:`): both readings keep their `[ADDR:bytes MNEMONIC]` trace comments, the label is reached by name from the jump, and the bytes stay identical. Never rewrite it as one `bit` line: the label has nowhere to go. `scripts/refactor/bitskip.py MAP` writes the form and `--scan` lists the sites. **Name the label for the value or case the branch-taken condition proves, and say which branch reaches it**: the tool prints the condition and warns when the name has a side word or negation (`BNE` taken is the other register state than `BEQ` taken). The hidden label is an INNER label for `scopeify.py`; run `bitskip.py` before `scopeify.py`.
- **A block used both as an array and member by member** (a shadow of the sprite registers, indexed `sta base,y` in a copy loop and written as `s0_y` elsewhere) needs both spellings: the namespace's `base` label for the loop and the named members for the single writes (`slot5`, or the hardware name). Both are defined from one declaration (`base+N` in the definition only), so the loop and the members cannot drift apart. A table of values that merely looks like addresses (frequencies, pattern numbers) carries `// NOT-POINTERS: reason` on its label line; `p1_complete.py` check 5 then lists it as waived instead of reporting it.
- **Variables inside the image.** A variable or table that lives in the image (a scratch byte after a table, a table of values, a self-modified operand) gets an **in-stream label at its address** in the source, not a `.label X = $ADDR` line in the symbols files: the export puts them in the symbols files, and converting them is one of the first passes of phase 1 (`phase1_method.md`, the order of passes). SMC operands named `LAB_xxxx_1` become `label:operand` forms.


## Local labels
Applies to: every project, both phases (decided with the user 2026-10-29: the relaxed anonymous-label rule below is the general one, because it reads better).
- **Local labels:** scope the routine (`Name: { ... }`) and name each label for what it means (`done`, `row_loop`, `go_behind`); a label used from another routine is global with a proper name. **Anonymous labels (`!:`, `!+`, `!-`) are allowed under the limits of the next section** (the general regime), and `scripts/anon_labels.py` lists what qualifies and converts it; `--strict` is the older, narrower regime (a trivial skip or a tiny loop that is the only local), for a project that wants it. More than ~3 non-trivial locals suggests splitting the routine.

## Structure and comments
Applies to: every project, except where a bullet says otherwise.
- **Label files.** Symbols live in label files by kind (`zero_page.asm`, `variables.asm`, `constants.asm`, `symbols.asm` as the index). **Keep the Ghidra XREF comments** with their labels, and the exporter's `[ADDR:bytes MNEMONIC]` end-of-line comments: they exist to trace back to the original code (decided with the user). Ghidra placeholder names inside these trace comments are allowed (they record what the original export called a thing); everywhere else the no-placeholder rule holds, in code and in prose comments. When a label is renamed its XREF lines are not rewritten. `p1_complete.py` ignores trace comments and counts the rest.
- Section banners (used by some projects; where a project does not use them, no `STATUS:  unknown` banner exists to block phase 1) (`SECTION:` / `RANGE:` / `STATUS: unknown|partial|understood` / `SUMMARY:`, optional `P1_ROUTINE_NAME:` in phase 2) are landmarks; add or refine one when a region is understood. `just sections`, `just todo`.
- **TODO markers are `// TODO(tag): headline`** (one tag per marker: `sound` needs listening, `user` needs the user's knowledge, `code` is plain work, `phase2` is a change for phase 2, `port` is a hardware dependency a port to another machine must replace (SID writes, raster timing, VIC bank, colour-RAM layout; kept separate from `phase2` so each list can be ticked off alone; not a phase 1 blocker), `name` is a provisional name awaiting confirmation, `block` is any other phase 1 blocker); detail follows on `//   ` lines; delete the marker when answered. A project that used `p2_todo:` writes `TODO(phase2):`, and a plain `TODO:` that blocks phase 1 becomes `TODO(block)`. **`TODO(name)` and `TODO(block)` are phase 1 blockers** (decided with the user); `p1_complete.py` counts them. `rename.py` and `set_comment.py` take the TODO as a fourth map column and write it as its own `// TODO(tag):` line; a `TODO(tag):` inside prose is split off. `rename.py` and `set_comment.py` replace an older block above a label only when it looks like a description they wrote (at most 8 lines, no banner, no XREF or access notes, not another symbol's note); anything else is kept and reported as `REVIEW kept ...`: merge it by hand. A map cell holds a line break as the two characters `\n`, never a real newline; several TODOs go in column 4 as `TODO(name): a\nTODO(user): b`.
- Do not read the monolith whole: grep a label in `symbols.asm`, read around it, follow cross-references.
- **Text as text** (decided with the user): every string the game contains is written in the source **as readable text**, through the game's own encoding (a macro such as `Text("...")`, or `.text` with an `.encoding`), never as rows of `.byte` values. The encoding is documented per project (`docs/text_and_encodings.md`), each string or table has a label, and where the control codes mix with the letters they have named constants. A byte row that decodes as text is a sign the text has not been recovered yet.


## Comment rules
Applies to: projects that adopt them (decided with the user 2026-10-29 in one project; others adopt them when they choose).
Enforced by `scripts/comment_check.py` (`just comment-check`; every threshold is an option; `--list` shows offenders; an optional `tools/comment_baseline.tsv` makes it a ratchet for a source that is not yet clean, and `--write` only ever lowers the baseline).
- **No echo:** a comment says something the line does not. A data row keeps `// [addr]` and nothing that repeats it: no list of the operand names after a `.word` row, no ASCII dump after a `.byte` row (an exporter writes both; `comment_check.py --fix` strips them, rule `echo`). The same goes for a comment that only restates an instruction.
- **Width:** wrap comment text at 128 columns; nothing passes 150. A long note is several `//` lines. A data row is as wide as its bytes, so only its comment is limited (100 columns).
- **Label line** (`Name:  // ...`): a one-line summary, at most 80 characters (ideally under 60). The detail is a block comment **above** the label, wrapped at 128, above the `XREF` lines if the project keeps them.
- **Routine:** the block above the label says what it does and why; add `In:` / `Out:` / `Clobbers:` lines when they are not obvious.
- **Code line:** the end-of-line comment is the `[addr:bytes mnemonic]` text plus at most a short note; a longer remark goes on its own `//` line above, indented like the code. Say why, not what. Write `probably` when unsure.
- **Symbol files:** `// name: description` above the `.label`, wrapped at 128.
- **Tables:** every table has a column list in the block above its label: what it is, record count and size, who reads it, then one line per field (`//   byte  field  meaning`). A table with one obvious column may use a single legend line instead. One record per line; a data-row comment keeps the `// [addr]  note` form (`just progress` counts a row with that form as classified). A set of tables of one format (enemy paths, room lists) documents the format once, above the first.
- **One record per row:** a table of fixed-size records is written one record per `.byte` row (a header of a list on its own row, a list's end marker on its own row), never in the exporter's 16-byte rows where a record straddles two rows and the end of a list disappears. `refactor/records.py LABEL --stride N [--end HEX]` reshapes a table without changing a byte; the stride is the one the reading routine uses. A block that runs on past its end marker is a label missing (`sentinel_scan.py`).
- **Markers:** `TODO(tag):` starts the comment line (tags above); the first line is a complete headline (the whole text if it fits) so `just todo` lists something useful; detail follows on `//   ` lines. Mark `TODO(phase2)` only where the evidence is absolute.
- **Names in prose:** write the real label name, not an address, unless the address is the point; hex in upper case (`$4E42`).
- **Migration:** reflow in mechanical passes (clean split of long label comments, paragraph-aware wrapping that treats a `TODO(phase2)` headline specially), hand-write the rest, and check byte identity after each pass. Never reflow without a checkpoint to return to.


## Anonymous labels (the general regime)
Applies to: every project (it was adopted for all; source written under the older "trivial skip only" rule can be converted where it qualifies).
A local branch target may be anonymous only when all of these hold:
1. the label and every branch or jump to it are in the same routine (between two named labels);
2. nothing else refers to it: no other routine, jump table, data row or self-modifying code;
3. each reference is at most two anonymous labels away (`!+`, `!-`, `!++`, `!--`; never `!+++` / `!---`), counting the target, in the final layout;
4. each reference is at most 40 source lines from its target.
Anything else keeps a name: routine entries, jump-table targets, SMC operands and targets, labels used from several places. A routine whose only other reference is far away keeps the named label and adds an anonymous one directly after it for the near retry loop (`Name:` then `!:` ... `bcc !-`). Keep the `// [addr:... BNE $xxxx]` comment on the branch: it shows the real target. Adding or removing a `!:` changes the count for every reference that spans it, so run `just verify` after any change near one. `scripts/anon_labels.py --check` (recipe `anon-check`) fails on `!+++` / `!---` and on any reference over the limits; `anon_labels.py` alone lists the candidates and `--write` converts them (recounting every reference, because adding a label can push another one over the limit). `anon_labels.py --check` also fails on an anonymous reference that leaves its routine (a different scope, or past a called global entry).


## Relocatability
Applies to: every project (decided with the user 2026-10-29).
Phase 1 stays byte-identical, but moving a block of variables must take one number. Rules:
- **A block of consecutive bytes that code addresses one by one** (sprite positions, a random state) is a `.namespace` in the symbols file with a `base` label (for `,x` loops) and one member per byte defined as `base+N`; code writes `zp_sprite_x.slot5` and `zp_sprite_x.base,x`, never `zp_sprite_x+5`. Name members after what the code proves (hardware sprite number, field), not a guessed role.
- **Aliases** of one byte (two uses of a shared variable) are `.label alias = primary`, never a second `$` number, and come **after** the primary in the file. Give the alias a `TODO(phase2)` to split the byte in phase 2.
- **Pointer high bytes** are `ptr+1` defined once (`.label ptr_hi = ptr+1`). `+N` is allowed in a DEFINITION (`.label ptr_hi = ptr+1`, `.label x_red = x+1`, a member `base+N`) and nowhere else: uses always go through a name. `label+n,x` into a table (a record offset or a row) is a different case and stays.
- **Strides, counts and ranges** that the code spells as a number get a constant (`ENEMY_SLOT_SIZE`, `ENEMY_SLOTS`); a loop that clears or copies a range takes its length from labels (`#last.member-first.base`). Where the code does the arithmetic with shifts and adds, leave a `TODO(phase2)` (it only works for one size).
- **A variable inside the code or data image** (a scratch byte after a table) gets a `TODO(phase2)`: a register, the stack or a zero-page temporary replaces it. Label it at its place in the source, not with a `$` number in the symbols file, so it moves with the image.
- **Test:** copy the project to a scratch directory, move one block (change its `base`), assemble, and diff against the reference: only the operand bytes of that block's users may differ (56 bytes for the sprite blocks, 35 for `zp_cursor_x`). Anything else is a hidden dependency to find.
- **Phase 2** places the same blocks in a `virtual` segment with the one start address (`*=$02 "Zero page" virtual`, then declarations; `.segmentdef` for further regions); contiguity needed by `,x` loops and `(zp),y` pointer pairs (low byte then high byte) must stay a single declared block.
- **Anchored addresses (phase 2):** the layout is free except what hardware reads at a fixed address (bitmap, character set, cycle-sensitive interrupt code, the page a raster interrupt chain lives in). Anchor those with `*=` / `.pc` blocks and assert the address, so a change that would move them fails the build. A fixed address is a property of the hardware, not of the game.
- **Pointer data** is `.word label` or `#<label` / `#>label`, never a literal, so a table or block can move.
- **Checks after a phase 2 change that adds or removes bytes:** a scan for what would break if the image or a variable moved (indirect addressing, SMC, pointer tables), then a layout fuzz (insert N bytes at chosen places, rebuild, run the routine tests and traces on each variant), then a screenshot: a displaced bitmap passes every trace and only the picture shows it. The project's recipes name them (`just reloc`, `just fuzz-layout`).


## Working rules
Applies to: every project.
- **Terminology follows the original author** when there is one (use the author's word, not a synonym: the identifiers, comments and docs all change together).
- **Bulk rewrites of comments or names:** copy the files to a scratch directory first and make every pass repeatable from that copy. A mechanical reflow of paragraphs will produce ragged text; if a pass is wrong, re-run the fixed pass from the copy rather than patching its output. Check byte identity (`just verify`) after each pass.
- **Dead code and write-only variables** found while naming are recorded as `TODO(phase2)` with the facts only (what is always taken, what is never read); say "probably" for intent. This includes whole unreferenced blocks: leftover data, or a utility nothing calls (no reference in the image, never executed in the tracer runs). Label it, decode or comment it, and put `TODO(phase2): remove? unreferenced, never executed` on its first label; the owner decides in phase 2. A slice is not done until each such block carries the marker. Do not delete them in phase 1.
- **A name-only pass uses `scripts/refactor/`** (`rename`, `drop_labels`, `replace_raw`, `replace_imm`, `move_img`, `scopeify`, `set_comment`, `uses`: each takes a TSV map, prints per-name counts in a dry run, and changes code only): read the counts, `--write`, then `just verify`. Write a one-off migration script only for what these do not cover. `refactor/README.md` has the pass order.
- **Tools that keep the source tidy:** `just align` (comment columns), `just anon-check` (`anon_labels.py --check`), `just comment-check` (`comment_check.py`), `p1_complete.py --range LO-HI --allow-marked` to call a slice clean. Run `just verify` after any change.


## Hygiene
Applies to: every project.
- **No guesses** about what art, sounds or modes are; ask. 
- Anything the hardware reads at a fixed address (bitmap, charset) must stay anchored in phase 2; check with a screenshot, not only traces.
- State that holds an address is not behaviour: keep it out of golden-trace state.
- `framework/` is generic; no project value inside it (`project.config` carries them).
- Never edit `reference/`, `originals/` or a mirror directly; one-way flows only.
- Emulator tests must run unattended (judge by screenshot, not by a PC sample).
